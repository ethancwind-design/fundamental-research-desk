Opening questions and follow-up branches

1. Does this specific workshop example actually run its model locally on the named device?

If yesWhich model file, quantisation, runtime version and accelerator are used, and which network calls remain necessary?
If noWhich step runs elsewhere—download, inference, retrieval or a user interface—and how should I label the example?
If vagueCan we draw the device-to-model data path rather than treating a Pi-connected screen as local inference?
Public evidencePublic exercise instructions, model/runtime identifiers and a public diagram; no attendee account access.
PurposeDevice visibility does not establish where computation takes place.
Your queue

2. Is there a predeclared output-quality threshold for the task, beyond simply producing text?

If yesCan I reuse the same public prompts and scoring rule on my own hardware?
If noWould a small extraction/classification task with known answers be a fair classroom follow-up?
If vagueWhich error would make an output unusable for the proposed application, and can we record that before comparing speed?
Public evidencePublic prompt set or researcher-created synthetic inputs with a fixed acceptance rule.
PurposeA faster response is not useful if it fails the same task.
Your queue

If yesWhich versions, storage, memory and preparatory downloads should they record?
If noWhat resources or prior knowledge are omitted from the demonstration, and what is the lowest-cost way to learn them?
If vagueSeparate one-time model download, first load, first answer and repeated answer; which measurement is being described?

PurposeHuman setup effort and hardware readiness are directly observable.
