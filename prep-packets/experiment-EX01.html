From parts list to a working local display

What human work and extra equipment are required to make one Pi useful and reproducible for a second operator?

Define the test before you start

Operator task: Install the chosen official OS, show the local catalogue full-screen, select three predetermined entries, then reboot normally and restore the same working display from a written runbook.

Success rule: Predeclare: all ten dummy entries render, all three selections return the expected status, and the post-reboot task works. Record completion time even if the personal target is missed; do not redefine success after seeing results.

Materials

  • Borrowed/owned Pi and model-appropriate supply, compatible storage, cables, display and input devices.
  • A second spare storage card and a laptop; no hardware order made.
  • A local test page with ten researcher-written dummy catalogue entries and a button that changes a visible status.

4–6 active hours over one or two days; equipment borrowed where possible. Costs remain blank until the user chooses and records real purchases.

Repeatable procedure

Step 1

DoFreeze board model/RAM, OS and Imager versions, image identifier, storage, supply, cooling and display resolution; list every missing item before building.
RecordConfiguration ID; owned/borrowed/missing; planned versus actual item list.

Step 2

DoTime planning, image download, image writing, assembly, first access and application setup separately. Pause the active-work clock during unattended downloads but retain wall-clock time.
RecordPhase start/end; active minutes; elapsed minutes; error and help source.

Step 3

DoExecute the fixed three-selection task ten times after one declared practice run. Keep expected results fixed and record failures.
RecordThirty task actions; success/failure; assistance; time boundary.

Step 4

DoPerform one normal shutdown/restart and verify the task again. Then rebuild from a fresh spare image once.
RecordReboot-to-useful-task time; fresh-build time; differences from first build.

Step 5

DoHave a consenting second operator follow the runbook from the declared start state without verbal coaching. Log any intervention needed, then give them the corrected instructions.
RecordPrior experience; step; intervention; result; omitted prerequisite.

Controls, stopping rules and limits

Hold these conditions fixed

  • Same application and dummy data across runs; no private account or external API dependency.
  • Separate novice setup effort from device malfunction.
  • Do not hide unsuccessful attempts or silently substitute accessories.

Stop when

  • Stop if equipment compatibility is uncertain or the owner declines a change.
  • Do not use the user’s normal storage image for destructive reimaging.

What this cannot establish

  • One device and two operators are a case study, not an estimate of population usability or failure rate.
  • A borrowed monitor still belongs in the full system inventory even when incremental cash spending is zero.
